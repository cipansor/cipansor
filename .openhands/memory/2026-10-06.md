# 2026-10-06 — OpenHands support for cipansor

Added the OpenHands-side config that mirrors what `.claude/` already does.
Machine-specific facts (sandbox versions, host paths, the no-Docker Postgres
recipe) live in the user-tier memory (`~/.openhands/memory/`), not here.

## `.openhands/setup.sh`

OpenHands runs this at the start of every conversation on the repo
(docs.openhands.dev → Usage → Customization → Repository → "Setup Script").
Idempotent, non-fatal failures; does **not** seed or start the stack. It does:
corepack→pnpm, `pnpm install`, build `@cipansor/shared`, `prisma generate`,
Playwright Chromium, then Postgres+Redis (Docker if a daemon exists, else apt).
Verified cold and warm runs on the sandbox, exit 0 both.

## `.openhands/hooks.json` + `.openhands/hooks/`

Ported the two mechanical `.claude/hooks`. Research facts (from SDK source):

- **Tool names differ from Claude's**: `terminal` (Claude `Bash`), `file_editor`
  (Claude `Write`/`Edit`/`MultiEdit`). `file_editor` input keys are `path`,
  `command` (`view`/`create`/`str_replace`/`insert`), `file_text`, `new_str`.
  `guard.sh` normalizes both vocabularies so one script serves either tool.
- **`hooks.json`** accepts snake_case (`pre_tool_use`) or PascalCase event keys;
  `matcher` is `*`, an exact name, or a regex (matched with `re.fullmatch`).
- **Hook contract**: JSON event on stdin (`event_type`, `tool_name`, `tool_input`,
  `session_id`, `working_dir`), env `OPENHANDS_PROJECT_DIR`, `OPENHANDS_TOOL_NAME`,
  `OPENHANDS_EVENT_TYPE`, `OPENHANDS_SESSION_ID`. Exit 0 allow, exit 2 block;
  stdout JSON may carry `{"decision":"deny","reason":...,"additionalContext":...}`.
- **Not ported**: the Claude records/compaction hooks (`pre-compact-sync`,
  `context-sync-warn`, `stop-sync-records`, `stop-sync-baseline`, `main-ci-watch`).
  They lean on Claude's `stop_hook_active` loop guard and its `PreCompact` event,
  which OpenHands lacks; `session-bootstrap.sh` is superseded by `setup.sh`. The
  user chose (2026-10-06) not to build an OpenHands records reminder.

Verified: 16/16 guard cases, 5/5 normal ops pass, adapter forwards a block.

## Skills and memory: the two tools disagree on paths

- **Skills.** OpenHands loads project skills from `.agents/skills/` (preferred),
  `.openhands/skills/`, `.openhands/microagents/` (legacy) — **never**
  `.claude/skills/`. Claude Code is hard-coded to `.claude/skills/` (+ personal,
  nested, `--add-dir`), and no setting or env adds `.agents/`; the two feature
  requests asking for it (#66352, #22902) were closed unimplemented. **The bridge
  is a symlink, and the docs allow it both ways.** Chosen: skills stay canonical
  in `.claude/skills/`, with `.agents/skills -> ../.claude/skills`. Verified the
  OpenHands loader follows it and the repo's tree-walking guard tests still pass.
- **Memory.** OpenHands auto-loads `<repo>/.openhands/memory/MEMORY.md`
  (hard-coded path, 6000-char budget, truncated from the top) plus the user tier
  `~/.openhands/memory/MEMORY.md`. Claude auto-loads `.claude/memory/INDEX.md`
  through `CLAUDE.md` imports. These are different files with different shapes, so
  they are **not** merged: `.claude/memory/` stays the full record; this
  `.openhands/memory/MEMORY.md` is a thin pointer index kept under the budget.
- `AGENTS.md` is read by both (Claude only when the folder has no `CLAUDE.md`).

## Review round 1 — all findings from PR #660 (2026-10-06)

Fixed each finding in place; the same fix was applied to `.claude/` where the
OpenHands file is a port of it (one source, no drift).

- **`stack` fallback: `--auth=trust` (CWE-306).** Replaced with
  `initdb -A scram-sha-256 --pwfile`, so the fallback cluster authenticates.
- **`stack` fallback: `/tmp/pgsock` missing.** `pg_ctl -k` aborts without it;
  added `install -d -o pgrunner -g pgrunner /tmp/pgsock` and a `pg_isready`
  wait loop before `createdb` (mirrors `scripts/dev-stack.sh:15-16`).
- **`setup.sh`: Playwright engines.** `install --with-deps chromium` left
  Firefox/WebKit missing, so the full `test:e2e` (default projects include
  firefox + webkit + mobile-safari) failed to launch. Now installs all three.
- **`setup.sh`: lockfile rewrite.** The `|| pnpm install` fallback could rewrite
  `pnpm-lock.yaml` on a routine session start. Removed; warn and leave the tree.
- **`format-before-push.sh` adapter: dropped `working_dir`.** Now forwards it as
  `cwd`; the shared check resolves `cd` / `git -C` from it, so a worktree push is
  checked against the right commit range.
- **`guard.sh`: implicit main push.** `git push` / `git push origin` on `main`
  (or a branch whose upstream is `main`) named no branch and slipped through.
  Both guards now resolve the repo (`cwd`, `cd`, `git -C`) and the branch/upstream
  and refuse. Explicit `git push origin main` / `HEAD:main` still refused.
- **`sync-records`: Claude-only steps.** Step 4 now names the OpenHands index
  (`.openhands/memory/MEMORY.md`), step 6 is marked Claude-only, step 7 drops the
  `/compact` sentence for OpenHands.

Verified: `bash -n` on all four hook scripts; guard matrix 8/8 (both tools),
upstream=main and `git -C` cases; adapter emits `cwd`; no false positives on
echo/commit-message/`maintenance-x`; other guard rules unchanged.

## Review round 2 — Devin findings (2026-10-06)

- **`stack` fallback password file (CWE-732).** `printf > /tmp/pgpass.txt` under
  the default 022 umask is world-readable. Wrapped in `( umask 077; … )` so it is
  0600 before `chown pgrunner` and deletion. (The `--auth=trust` and adapter
  `working_dir` findings were already fixed in `4cac4cb` — confirmed absent.)
- **Guard: `cd` before the push.** The guard resolved the repo from the event
  cwd only, so `cd /tmp/main-worktree && git push` from a feature checkout
  queried the feature branch and allowed it. Both guards now carry `here` across
  segments, updating it on `cd`, and resolve `git -C` relative to `here`.
- **Guard: explicit `HEAD` refspec.** `git push -u origin HEAD` (and
  `HEAD:HEAD`) pushes the current branch to its same-named remote branch; the
  branch's `merge` does not pick that destination, so treating it as a
  destination-free push blocked a legitimate upstream repair on a main-tracking
  branch. `resolve_refspec` now returns the actual destination (`HEAD` →
  current branch, `src:dst` → `dst`, bare → same name), and only a truly
  destination-free push consults `branch.<name>.merge`.
- **`setup.sh` warning.** Named network/registry failure as well as a stale
  lockfile, so the agent does not "fix" a valid lockfile after an outage.
- **`MEMORY.md` index.** The committed thin index said "Playwright Chromium";
  now the three engines. (The working copy was the runtime's own auto-memory —
  restored after, then the committed index was written deliberately.)

Not changed here: `scripts/dev-stack.sh` still runs `initdb --auth=trust` and
`scripts/dev-up.sh` hardcodes `/home/user/cipansor` + `postgresql/16`. It is a
pre-existing, container-coupled helper outside PR #660's scope, and it is coupled
to `dev-up.sh`'s passwordless `DATABASE_URL`, so it wants its own PR.

Verified: `bash -n` on the edited scripts; full guard matrix for both tools —
`git push`/`git push origin` on main → block; upstream=main → block;
`cd <main-worktree> && git push` → block; `git push -u origin HEAD` /
`HEAD:HEAD` → allow; `feat/x:main` / `HEAD:refs/heads/main` / `origin main` →
block; `feat/x`, `maintenance-x`, echo/commit-message → allow; schema and
sensitive-`.md` rules unchanged.

## Review round 3 — shell-expanded `cd` bypass (2026-10-06)

Devin: on `main`, `cd "$PWD" && git push` passed because `here` treated `$PWD`
as a literal directory — the join produced `<checkout>/$PWD`, `git rev-parse`
returned nothing, and the destination-free push was allowed. A failed
`cd /missing; git push` had the mirror problem: `here` advanced to `/missing`
while the shell stayed put.

- `resolve_dir(word, base)` now decides: a target containing `$` or a backtick is
  a shell expansion → `None`; a plain target that is an existing directory →
  that directory; a plain target that does not exist → `base` (the shell stays
  put, exactly what `cd` does). A `None` sets `uncertain`, and the next push is
  refused ("working directory is set by a shell expansion…"); a successful plain
  `cd` clears it.
- `push_repo_dir` also returns `None` for a `git -C "$VAR"` expansion.
- Fail-closed only fires when the command actually has a push, so
  `cd "$PWD" && ls` is still allowed. Explicit refspecs are refused too when
  uncertain — a push we cannot locate is not worth allowing.

Verified: `cd "$PWD"`, `` cd `pwd` ``, `cd "$HOME"`, `git -C "$PWD"` on `main` →
block; `cd /missing && git push` on `main` → block (stays on main); real
`cd /tmp/mainwt && git push` → block; feature matrix unchanged; `cd "$PWD" && ls`
→ allow.
